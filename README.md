Domain: E-commerce

# Flipkart E-commerce Decision Intelligence (synthetic data)

This repository answers three questions for a customer-analytics team: is the planning assumption about order value right, which customers will churn, and what kinds of shoppers exist. All data is synthetic (generated by `generate_data.py`); nothing here reflects real Flipkart data. Money is in INR. Order value and average order value are recorded in hundreds of INR, so 8.0 means INR 800.

Helper files `common.py` (loading, printing, split) and `models.py` (logistic regression, KNN, metrics) are imported by the Part scripts and never run a Part on import.

## How to run

From a clean clone, in this order:

```
pip install -r requirements.txt
python generate_data.py
python part1.py
python part2.py
python part3.py
python part4.py
```

`generate_data.py` must print `800 10 170 c6f249ba693f1ebeed318d6d5e18de23`. Each Part script regenerates its own files in `outputs/`. Part 4 rebuilds the Part 2 split, logistic model and chosen K through `models.py`, so it gives the same numbers as Part 2.

## Part 1 findings

**R1.1 Hypothesis test.** H0 was rejected: `z_stat` = 2.8930, which is larger than the critical value 1.96. A Type I error here would be concluding that the average order value is not INR 800 when it really is, and so needlessly revising the category plan. The gap `mean_value` - 8.0 is 0.9382 column units (8.9382 against 8.0), about INR 94 or 11.7% above the assumed INR 800. It is statistically clear (the 95% interval is 8.3026 to 9.5738), but practically modest per order; it only matters if plans are multiplied across very many orders. The spread is large (`sd_value` = 9.1723), so the mean is pulled up by a few big orders.

**R1.2 Sample size.** `n_required` = 1293 against the 800 rows available. To pin the average down to within half a unit (INR 50) at 95% confidence the team needs about 493 more orders; with 800 the margin is about 0.64 units (INR 64).

**R1.3 Gradient descent vs closed form.** `gd_slope_gap` = 0.0000. The squared-error cost is a single smooth bowl in slope and intercept, so repeated downhill steps with a sensible learning rate settle at the one minimum, which is exactly the least-squares line the formula gives (the cost stopped changing at 40.3698 by update 100).

**R1.4 Funnel check.** `resid_sd_ratio_raw` = 3.7525: residual spread in the upper half of fitted values is about 3.8 times the lower half, a clear funnel. `resid_sd_ratio_log` = 1.0396, so the log-log model removes it and the spread is roughly constant.

**R1.5 Multiple regression.** Using the mechanical 0.05 rule on the Task 1.7 coefficients, the predictors with absolute coefficient above 0.05 are ln(X4) (1.1576), X2 `complaint_count_90d` (0.0940), X3 `discount_order_share` (0.1067) and X6 `cod_flag` (0.1518). This is only a rule on raw coefficients in different units, not a ranking of importance. `mr_adj_r2` = 0.7403 against `loglog_adj_r2` = 0.6561, so the extra predictors earn their place (adjusted R-squared rises by about 0.084).

## Part 2 findings

**R2.1 Learning rates.** After 200 updates the losses from lowest to highest are 0.3703 (eta 1.0), 0.3776 (eta 0.1), 0.5091 (eta 0.01). A rate that is too small (0.01) crawls and is still far from the minimum; the largest rate (1.0) got closest without diverging on this standardised data, although such a large step can overshoot on other problems.

**R2.2 Weights and odds ratios.** The three largest absolute weights are X3 `discount_order_share` (0.9013), X1 `customer_tenure_months` (-0.5554) and X2 `complaint_count_90d` (0.5505). The largest odds ratio is `odds_ratio_X3` = 2.4629: a customer whose discount-order share is one training SD higher has about 2.5 times the odds of churning, other predictors held fixed.

**R2.3 Accuracy is weak here.** `blind_accuracy` = 0.7875 (predict "no churn" for everyone) against 0.8042 accuracy for the model at tau = 0.5, so the model is barely better than doing nothing on this score because churners are only about one in five. Lowering tau from 0.5 to 0.3 raised recall from 0.4706 to 0.7451 and lowered precision from 0.5455 to 0.4634.

**R2.4 Logistic vs KNN.** At tau = 0.3 logistic regression has `f1` 0.5714 and `recall` 0.7451; KNN (best K = 5) has `knn_f1` 0.3696 and `knn_recall` 0.3333. Logistic is clearly better.

**R2.5 Deployment.** I would deploy the logistic model at tau = 0.15 (`cost_tau`). On the test rows it costs INR 6,050 (`cost_test_at_tau`), against INR 11,800 at tau = 0.5 and INR 20,400 if nobody is flagged (`cost_test_flag_nobody`). The threshold was chosen on training rows so the test rows stay untouched and give an honest estimate of the cost.

## Part 3 findings

The mean vector of the standardised data is all zeros (PCA step 1), as expected after standardising.

**R3.1 Elbow.** Successive WCSS drops: WCSS(2) - WCSS(3) = 659.8282, WCSS(3) - WCSS(4) = 108.0739, WCSS(4) - WCSS(5) = 171.0575, WCSS(5) - WCSS(6) = 45.5466. The big drop is from 2 to 3 clusters and the next drop (108.07) is under half of it, so `elbow_k` = 3. The drops do not shrink steadily (4 to 5 is bigger than 3 to 4), because the pinned starting rows give one reproducible solution, not necessarily the global optimum.

**R3.2 Segments** (from `part3_segments.csv`):
- **A, "Steady loyal regulars"** (322 customers; tenure 47.5 months, 1.95 complaints, discount share 0.225, churn rate 0.0186). Action: reward loyalty with early access or perks instead of discounts, since they rarely leave.
- **B, "High-value but frustrated"** (255; 6.07 complaints, average order value 28.7 hundreds INR, churn rate 0.2353). Action: proactive service recovery, so complaints are resolved quickly before they leave.
- **C, "New bargain hunters"** (223; tenure 14.4 months, discount share 0.712, loyalty 38.5, churn rate 0.4664). Action: onboarding and second-purchase coupons plus a loyalty-programme nudge.

Segment C has the highest `outcome_rate`, 0.4664.

**R3.3 Dendrogram cuts.** Single linkage cuts into 4 clusters: {E1}, {E2, E3, E6}, {E4}, {E5}. Complete linkage cuts into 2 clusters: {E1, E4, E5} and {E2, E3, E6}. Single linkage joins on the closest pair, so its merge heights stay low (last merge 3.4) and the biggest gap falls early, between merges 2 and 3; complete linkage uses the farthest pair, so the final merge (E1 to E2, 7.9) is a huge jump and the biggest gap comes at the end. Average linkage agrees with complete (2 clusters).

**R3.4 PCA.** PC1 is driven by X1 tenure (+0.5317), X3 discount share (-0.5187), X5 loyalty (+0.4418), X2 complaints (-0.4100) and, weakly, X4 order value (-0.2916): long-tenure, high-loyalty customers on one side and discount-heavy, complaining customers on the other. Three components keep at least 80% of the variance (cumulative ratio 0.8616; two give 0.7593). `mean_pc1_segment_A/B/C` = 1.7773 / -0.7831 / -1.6709, so PC1 orders the segments A, B, C, the same order as their churn rates (0.0186, 0.2353, 0.4664).

## Part 4 findings

**R4.1 Best split.** S4 (tenure at most 24 months) has the highest information gain (0.1252) and Gini gain (0.0606): the short-tenure side churns at 86 of 188 (45.7%) and the longer-tenure side at 33 of 372 (8.9%), the cleanest separation of the four. A tree grown until every leaf is pure memorises noise in the training rows and generalises badly (overfits). A maximum depth, or a minimum number of rows per leaf, stops it growing too deep.

**R4.2 Which model to ship.** I would ship the logistic model: `f1` 0.5714 and `recall` 0.7451, against stump 0.5532 and 0.7647, hard vote 0.5344 and 0.6863, soft vote 0.5507 and 0.7451, KNN 0.3696 and 0.3333. Combining models did not help; neither vote beat the logistic model on F1, partly because the weak KNN dragged them down. (These rows use tau = 0.3, not the cost-chosen 0.15.)

**R4.3 AdaBoost.** After round 1 normalisation the two points h1 got wrong (points 3 and 7) carry a total weight of 0.5000. Round 2 trusts h2 more because its weighted error is lower (0.1667 against 0.2500), giving it a larger vote weight (alpha 0.8047 against 0.5493). The ensemble classifies 75% of the eight points correctly.

**R4.4 Architecture.**

| Layer (Model A, option 2) | Output shape | Parameters |
|---|---|---|
| Input | 28 x 28 x 1 | 0 |
| Conv 5x5, 6 filters, pad 2 | 28 x 28 x 6 | 156 |
| Max-pool 2x2, stride 2 | 14 x 14 x 6 | 0 |
| Conv 5x5, 16 filters, pad 0 | 10 x 10 x 16 | 2416 |
| Max-pool 2x2, stride 2 | 5 x 5 x 16 | 0 |
| Flatten | 400 | 0 |
| Dense 32 (ReLU) | 32 | 12832 |
| Dense 10 (output) | 10 | 330 |

`cnn_total` = 15734 against `mlp_total` = 13002 for the fully connected option. Convolution scales because filters are shared across positions: the 128 x 128 x 3 input costs `fc_layer_params` = 50332672 with a dense layer but only `conv_layer_params` = 1792 with 64 filters of 3 x 3.

Model B (recurrent network): W_xh is 128 x 64, W_hh is 128 x 128 and W_hy is 16 x 128, giving `rnn_total` = 26768. This number does not grow with longer sequences because the same weights are reused at every time step.

For 10 classes I would use ReLU in the hidden layers and softmax at the output with categorical cross-entropy loss. In a very deep plain network the gradient is multiplied by many small derivatives on its way back, so it shrinks toward zero and the early layers barely learn (vanishing gradients). A skip connection adds the input straight to a later layer, giving the gradient a short direct path back so early layers still get a useful signal.

## Model-choice memo

To: Head of the Retention Team

**Recommendation.** Put the logistic-regression churn model into production, flagging a customer when predicted churn probability is at least 0.15.

**Why this model.** On 240 held-out customers, logistic regression at 0.3 reached F1 0.5714 and recall 0.7451, well ahead of K-nearest neighbours (F1 0.3696, recall 0.3333). Combining models did not help: hard and soft votes scored F1 0.5344 and 0.5507, below logistic alone.

**Why 0.15.** A coupon to a customer who would have stayed costs about INR 50; a lost customer we did not flag costs about INR 400. The cheapest threshold on training data was 0.15. On the untouched test customers it costs INR 6,050, against INR 11,800 at the default 0.5 and INR 20,400 if we flag nobody, a saving of INR 14,350 (about 70%) over doing nothing.

**Risk.** The test set has only 51 churners and one random split, so these costs could move noticeably on new data. The INR 50 and INR 400 figures are planning estimates, and the data is synthetic. Re-check the threshold on fresh customers before launch.

**Next step.** Neither Model A (product-picture sorting) nor Model B (review-text topics) is worth building before this structured model is live, since the retention signal is already in the data we have.

## Limitations

1. The data is synthetic and generated from simple rules, so every result describes that generator, not real Flipkart customers.
2. One fixed 70/30 split leaves only 51 churners in the test set; test cost, F1 and the chosen K could change with a different split, and the best K and threshold are valid for this split only.
3. The INR 50 and INR 400 costs are assumed. The best threshold (0.15) depends directly on their ratio and would shift if the real costs differ.
4. K-means uses pinned starting rows, so the segments are one reproducible solution rather than the global optimum, and K = 3 was fixed for profiling regardless of the elbow.
5. Logistic regression is a linear model with no interactions, and order value is heavily right-skewed, so the raw-scale averages and regressions in Part 1 are sensitive to a few very large orders.
